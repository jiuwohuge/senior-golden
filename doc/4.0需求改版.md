## 2. 账户系统（Account System）

### 2.1 注册流程

流程：

```
输入邮箱 → 设置密码 → 设置基础资料 → 兴趣标签选择 → 进入新手引导写信
```

注册阶段收集：

- 昵称
- 头像
- 国家
- 城市（可选）
- 语言（跟随设备，见 §3.5）
- 兴趣标签

> 写作风格（§3.7）由系统依据用户信件内容自动生成，**注册阶段不收集**。

> 注册**不强制验证邮箱**，输入邮箱 + 密码即可完成。邮箱验证改为设置内的可选「邮箱验证绑定」（§2.9）。

> **注册确认步（UX）**：国家改为可搜索半屏列表（避免超长下拉）；兴趣摘要展示**标签名称**（非整数字数「3」）。文案使用慢邮/信件/笔友表述，**不使用**旧产品「明信片墙 / 名录」用语。

### 2.2 登录方式

支持：

- 邮箱 + 密码
- Apple 登录（可选）
- Google 登录（可选）

### 2.3 密码规则

规则：

- 8~20 位字符
- 必须包含字母和数字
- 支持修改密码
- 支持重置密码（邮箱验证）

### 2.4 登录记录

记录字段：

```json
{
  "login_time": "",
  "ip_address": "",
  "device_id": "",
  "user_agent": ""
}
```

### 2.5 异常登录规则

触发条件（满足 2 项）：

- IP 国家变化
- 设备变化
- 登录时间异常
- 24 小时内地理距离变化 > 1000km

### 2.6 风险处理

- **轻风险**：邮箱验证
- **中风险**：限制登录、二次验证
- **高风险**：冻结账号

### 2.7 账号管理

支持：

- 修改邮箱
- 修改密码
- 注销账号（7 天冷静期）
- 永久删除账号
- 账号冻结

### 2.8 新手引导（首封信）

新用户完成注册与基础资料后，引导写出**第一封信**，完成冷启动闭环：

- 默认走 **POST_OFFICE 模式**（无需先找人，降低门槛）
- 提供**信件助手**（§4.6）与信纸/商用模板帮助表达；**不使用**「自由书写 / 叙旧」等话题芯片快捷条
- 首封信在匹配时优先分配给高回信意愿用户（§7.5 新用户机制）与新用户保护池（§15.5）
- 引导完成后，进入邮局首页（§11）
- 首封引导写信桌**不展示**「存草稿 / 撤销助手改动」（降低干扰；正式写信桌可用）

### 2.9 邮箱验证绑定

- **适用范围**：**仅邮箱注册账号**；三方登录（Apple / Google）无此功能
- **入口**：设置 → 账号与安全 → 邮箱验证绑定（§13）
- **作用**：验证邮箱真实性，用于安全通知、密码重置、账号找回
- **流程**：`发送验证码到邮箱 → 输入验证码 → 标记已验证`
- **状态**：账号维护 `email_verified: false | true`；注册后默认 `false`，**未验证不阻断正常使用**
- **提示**：可在设置/安全场景对未验证邮箱给出温和提醒，不强制

## 3. 用户系统（User System）

### 3.1 基础资料

用户对象：

```json
{
  "user_id": "",
  "nickname": "",
  "avatar": "",
  "gender": "male | female",
  "birthday": "",
  "bio": "",
  "country": "",
  "city": "",
  "language": "en-US",
  "interest_tags": [],
  "writing_style": "concise | narrative | emotional"
}
```

> 数据结构为参考；`country/city`（§3.3）、`language`（§3.5）、`interest_tags`（§3.6）、`writing_style`（§3.7）为匹配算法（§7）的关键输入。

### 3.2 用户主页

用户主页用于：

- 用户发现
- 写第一封信
- 建立笔友关系

展示：

- 头像
- 昵称
- 年龄
- 国家 / 城市
- 语言
- 个人简介
- 兴趣标签（例如：旅行、摄影、阅读）
- 通信状态（派生展示态：陌生 / 通信中 / 可添加笔友 / 申请中 / 笔友，见 §10.3）

### 3.3 国家与地区（自动定位优先）

国家 / 地区**自动获取**，**仅在自动定位失败时才让用户手动选择**。

获取优先级（逐级降级）：

1. **GPS 定位**（已授权）：经纬度 → 反向地理编码 → 国家 / 地区（最准，需定位权限）
2. **IP 定位**（服务端）：客户端 IP → 国家 / 地区（免权限，国家级较准；VPN / 代理可能偏差）
3. **设备区域**（locale / region）：设备地区设置作为兜底提示
4. **用户手动选择**：以上均失败时，展示 ISO 国家 / 地区列表供选择

补充：

- 面向 45+，**默认优先"IP + 设备区域"等免权限方式**，减少定位授权打扰；GPS 为可选增强
- 用户始终可在资料编辑中手动修正国家 / 地区
- 格式：ISO 3166 国家 / 地区编码
- 与 §3.4 距离计算一致：GPS 经纬度 → IP 经纬度 → 兜底

### 3.4 距离计算

用于：

- 邮件延迟计算
- 推荐排序

计算：

- 经纬度距离
- 公式：Haversine distance

降级策略：

- **无经纬度**：直接用 IP 获取经纬度
- **无 IP，或无法根据 IP 获取经纬度（极端）**：默认 2 天（注意其他情况不管多远都不能超过这个 2 天）

### 3.5 语言系统

- **界面语言（i18n）**：跟随设备语言。首期仅本地化 **中文 / 英语**；其他设备语言**回退英语**，暂不参与国际化。
- **测试开关**：设置中提供 中文 / 英语 手动切换，**仅用于测试**，上线以设备语言为准。
- **用户语言字段** `language`：跟随设备语言（如 `en-US` / `zh-CN` / 其他），用于匹配的语言过滤与内容语言标识；非中英用户可正常使用，界面回退英语。

### 3.6 兴趣标签系统【优化】

用户标签，例如：

- 旅行
- 摄影
- 音乐
- 阅读
- 历史
- 美食
- 园艺
- 运动

用途：

- 用户推荐
- 邮局池匹配
- 笔友推荐

### 3.7 写作风格标签

系统生成：

- `concise`
- `narrative`
- `emotional`

生成依据：

- 平均句长
- 句子复杂度
- 情绪词比例

用途：

- 匹配推荐
- 笔友推荐

## 4. 信件系统（Letter System）

### 4.1 信件结构

```json
{
  "letter_id": "",
  "from_user": "",
  "to_user": null,
  "parent_letter_id": null,
  "mode": "POST_OFFICE | DIRECT | SELF_TIME",
  "content": {},
  "status": "",
  "audit_status": "PENDING_REVIEW | APPROVED | REJECTED",
  "created_at": "",
  "matched_at": null,
  "delivered_at": null,
  "read_at": null,
  "replied_at": null
}
```

> `status` 为投递主状态（§4.3），`audit_status` 为并行的审核状态（§4.3 / §15.6）；`parent_letter_id` 用于回信串联（§4.7）。

### 4.2 发送模式

v4.0 支持三种发送方式：

#### 方式 1：邮局模式（POST_OFFICE）

特点：

- 不指定用户
- 投递到邮局池
- 系统匹配接收者

流程：

```
用户写信 → 进入邮局池 → 匹配用户 → 开始投递
```

#### 方式 2：指定发送（DIRECT）

指定对象来源：

- 推荐用户（笔友页·推荐笔友）
- 找笔友筛选结果（笔友页·找笔友）
- 用户主页
- 通信对象（已通信未成笔友）
- 笔友

流程：

```
选择用户 → 写信 → 直接进入投递
```

> 说明：对"已通信但未成笔友"的对象继续写信，归入 **方式 2（DIRECT）** 的「通信对象」来源，不单独作为一种发送模式。

#### 方式 3：时光信（SELF_TIME）

- **特点**：发送给未来的自己
- **字段**：
  - `to_user = self`
  - `deliver_time = future timestamp`
- **规则**：
  - 不进入匹配系统
  - 定时开启

### 4.3 信件状态

**投递主状态**（`status`，随模式略有差异）：

```
POST_OFFICE : DRAFT → PENDING → MATCHED → DELIVERING → DELIVERED → READ → REPLIED → ARCHIVED
DIRECT/回信  : DRAFT → PENDING → DELIVERING → DELIVERED → READ → REPLIED → ARCHIVED   （无 MATCHED）
SELF_TIME   : DRAFT → SCHEDULED → DELIVERED（到点开启）→ READ → ARCHIVED             （不匹配、不回复）
```

**审核状态**（`audit_status`，与投递并行）：

```
PENDING_REVIEW（待审核）→ APPROVED（通过） | REJECTED（拒绝）
```

关键规则（对应 §15.6）：

- 通过前置英语敏感词后，`audit_status = PENDING_REVIEW` 并**照常进入投递**
- **送达闸门**：`DELIVERED` 前必须 `APPROVED`；若在途窗口内被判 `REJECTED` → 中止投递、不送达、退还额度
- SELF_TIME 仅本人可见，可按管理后台配置豁免或走轻量审核

### 4.4 信件列表展示状态【新增】

信箱中展示关系状态：

```
通信中 → 可添加笔友 → 笔友
```

示例：

```
Tom
最近来信：天气越来越冷了
通信：5 封
状态：可添加笔友
[继续写信]  [添加笔友]
```

### 4.5 添加笔友入口【新增】

- **入口**（三处一致，见 §10.4）：
  - 信箱前两个 Tab（收到 / 发出）中"可添加笔友"的信件项
  - 对方用户主页（§12.5）
  - 邮局关系消息中的"关系提醒"（§11.3 类型 2）
- **显示条件**：见 §10.5「添加笔友按钮显示规则」
- **按钮**：`[添加笔友]`

### 4.6 写信页（Compose）与信件内容

写信页是从**邮局（首页）写信入口**进入的核心创作页，产出一封信的 `content`。

内容结构（参考）：

```json
{
  "text": "",
  "images": [],
  "skin_id": "default",
  "font_id": "default"
}
```

字段说明：

| 字段 | 说明 | 商业化 |
|------|------|--------|
| `text` | 正文（必填，含长度上限，可配置） | 免费 |
| `images` | 图片附件（上限张数可配置，OSS 存储） | 免费/受限 |
| `skin_id` | 信纸/皮肤样式 | 默认免费，付费皮肤见 §16 |
| `font_id` | 字体样式 | 默认免费，付费字体见 §16 |

写信页规则：

- 收件人来源由发送模式决定：POST_OFFICE 不选人；DIRECT 已带对象；SELF_TIME 为自己
- **写信桌收件人切换**（非前置锁定时）：仅「有缘人 / 未来的自己」；**不含**从桌面再选笔友（与 §11.5 分流一致）
- **DIRECT 锁定**：从用户主页 / 笔友 / 回信等入口已带 `peerId` 进入时，收件人展示对方昵称且不可改回邮局/自己
- 提交前校验：正文非空、额度充足（§11.5）、内容安全前置过滤（§15.6）
- 支持存草稿（草稿箱见 §13）；提交后进入投递系统（§6）并触发投递动画（§5.4）
- **信件助手**（可选，Spring AI / DeepSeek）：用户主动打开后生成建议，**不自动覆盖正文**
  - 润色类模式（`warmer` / `natural` / `continue` / `shorten`）：对照后由用户确认「替换原文」
  - 灵感类模式（`inspire`）：返回可聊/可分享话题，用户勾选后**追加到文末**（不整篇替换）
  - 应用助手改动后提供**持久撤销**（恢复应用前快照）；助手 UI 为全屏，禁止点遮罩误关导致结果丢失

### 4.7 回信机制

回信是对某封已收到信件的回复，本质是一次**新的发信**，并关联原信。

- **关联**：回信携带 `parent_letter_id`，在信箱中形成往来串联
- **投递**：回信同样走投递系统，延迟按当前关系推导（笔友更快、非笔友保持慢节奏，见 §6.1）
- **往来计数**：一次有效回信使双方 `letter_count` 增加，用于派生"可添加笔友"（§10.5）
- **额度**：回信计入每日发送额度（与写信一致，见 §15.4）
- **入口（读信页）**：
  - **仅收件人**、且信件已 `DELIVERED`：显示主行动 `[回信]`，进入写信桌（DIRECT 锁定对方 + `parent_letter_id`）
  - **发件人视角**（查看自己发出的信 / 在途）：**不展示**回信输入框、草稿框或置灰「发送回信」
  - 回信写作在写信桌完成（含信件助手），不在读信页内嵌大输入区（适老化：一屏一主张）

## 5. 时间与仪式系统（Time & Ritual System）

### 5.1 可见时间字段

用户可见：

- `created_at`（创建时间）
- `sent_time`（发送时间）
- `estimated_delivery_time`（预计送达时间）
- `delivered_at`（送达时间）
- `read_at`（阅读时间）
- `replied_at`（回复时间）

### 5.2 用户时间轴（Timeline）

每个用户拥有统一时间轴，包含：

- 收到的信件
- 发出的信件
- 时光信
- 关系事件

示例：

```
2026-07-01  收到 Anna 的信
2026-07-03  回复 Anna
2026-07-10  成为笔友
2026-08-01  开启时光信
```

### 5.3 信件事件流

事件：

- `LetterCreated`
- `MatchFound`
- `QueueEntered`
- `DeliveryStarted`
- `TransitUpdated`
- `Delivered`
- `Read`
- `Replied`
- `RelationshipChanged`

用途：

- 状态追踪
- 时间轴展示
- 行为分析

### 5.4 仪式系统（Ritual）

"慢邮件"的情感价值来自仪式感，贯穿写—寄—收三个阶段。

- **邮戳**：每封信生成邮戳，展示 寄出地 → 送达地 的路由、寄出时间、当前状态（在途 / 已达）
- **投递动画**：信件封装 + 路径推进的过渡动画（写信提交后、列表进入在途时）
- **开信仪式**：拆封动画 + 邮戳显示 + 正文分段展开，弱化"即时消息"感
- **信纸/皮肤**：写信页与阅读页的信纸样式（默认免费样式；付费皮肤见 §16）

> 仪式表现为体验层，不改变信件数据与状态机；皮肤/信纸的付费部分落在商业系统。

## 6. 投递系统（Delivery Engine）

### 6.1 延迟计算

邮件到达时间：

```
delay = 基础时间 + 距离权重 + 关系权重 + 随机扰动
```

影响因素：

- **距离**：距离越远，延迟越长
- **关系**：
  - 笔友：降低延迟
  - 陌生用户：保持慢节奏

延迟区间（可配置）：

- 存在有效延迟区间 `[下限, 上限]`，具体数值由配置驱动（见 §3.4 距离降级）
- **上限默认 2 天**：任何情况下延迟不超过 2 天；无法获取位置时也按 2 天兜底
- 笔友 / 近距离取区间下限侧，速度更快但仍保留"寄达"感；陌生 / 远距离偏上限侧

### 6.2 投递类型

> 核心原则：**投递速度始终由 §6.1（距离 + 关系）决定**（陌生仍慢、笔友更快）。发送模式只决定"是否需要匹配收件人"，**不单独决定快慢**。

#### 1. POST_OFFICE（需匹配）

- **用于**：不指定收件人，投递到邮局池
- **流程**：`写信 → 匹配收件人 → 按 §6.1 计算延迟 → 运输 → 送达`

#### 2. DIRECT（已指定收件人，跳过匹配）

- **用于**：已指定对象（推荐/主页/通信对象/笔友）
- **流程**：`写信 → 跳过匹配 → 按 §6.1 计算延迟 → 运输 → 送达`
- **注意**：对**陌生人**的 DIRECT（如从主页写第一封信）**仍走慢节奏**；只有笔友/近距离才更快

#### 3. SELF_TIME（定时）

- **用于**：时光信
- **触发**：根据 `deliver_time` 定时开启，不计距离/关系

### 6.3 技术实现

- **本期**：PostgreSQL + 定时任务（`@Scheduled`）扫描到期信件并推进投递
- **后续可优化方向**：Redis ZSet 延迟队列（暂不考虑，Kafka 不引入）

## 7. 匹配系统（Match Engine）

### 7.0 定位

匹配系统是**推荐与分发的算法规则引擎**（内部能力，可持续优化），**本身不是独立页面**。它服务两处：

1. **POST_OFFICE 收件人分配**：邮局模式的信件在池中找到合适接收者
2. **笔友页「每日推荐用户」**：为 §9 推荐提供候选与排序

> 用户看到的是「笔友页的每日推荐」（§9）与「收到的邮局信」，匹配算法在幕后运行。

### 7.1 匹配流程

```
候选人过滤 → 用户特征提取 → Score 计算 → 排序 → 分发
```

### 7.2 过滤规则

过滤：

- 语言不匹配
- 用户拉黑
- 用户屏蔽
- 不活跃用户
- 收信超过限制
- 风控异常用户

活跃定义：72 小时内有行为。

补充规则：

- **收信上限**：单用户每日可被投递的邮局信数量有上限（数值由配置驱动），达到上限的用户不再进入候选，避免热门用户被淹没。
- **新用户例外**：新用户虽无 72h 行为记录，仍通过「新用户保护池」（§15.5）纳入匹配，避免冷启动无法被匹配。

### 7.3 Score 计算

| 因素 | 权重 |
|------|------|
| 情绪匹配 | 0.30 |
| 兴趣匹配 | 0.20 |
| 表达风格 | 0.15 |
| 时间匹配 | 0.10 |
| 地理 / 语言 | 0.10 |
| 新鲜度 | 0.10 |
| 随机探索 | 0.05 |

> **分阶段落地**：`情绪匹配` 与 `表达风格` 依赖 NLP，冷启动期（AI 未接入时）这两项降级——用兴趣标签/写作风格标签的近似规则代替，其权重可临时并入 `兴趣匹配`。待接入 AI（如 DeepSeek）后再启用真实语义特征。权重为可调参数，非硬编码。

### 7.4 分发策略

| 比例 | 对象 |
|------|------|
| 60% | 高匹配用户 |
| 30% | 中匹配用户 |
| 10% | 探索用户 |

目的，避免：

- 只推荐热门用户
- 新用户无法交流

### 7.5 新用户机制

前 3 封信：

- **提升**：高回复用户概率、匹配质量
- **避免**：新用户进入无人回复状态

## 9. 推荐系统（Recommendation System）

### 9.1 推荐形式

### 9.2 推荐来源

- 昵称

## 10. 关系系统（Relationship System）

### 10.1 关系定位

关系系统用于管理用户之间从陌生到笔友的发展过程。

核心原则：

- 通信关系 ≠ 笔友关系
- 笔友关系来自真实通信
- 不通过简单关注建立关系

用户关系成长：

```
陌生用户 → 通信对象 → 可添加笔友 → 笔友
```

### 10.2 关系模型（极简）

后端**只持久化"笔友关系"**这一件事，加上一个过渡态：

| 关系 | 含义 | 是否持久化 |
|------|------|-----------|
| 笔友（PENPAL） | 双方已确认的笔友 | 是 |
| 笔友申请中（PENDING） | 已发起申请、等待对方确认 | 是（临时） |
| 非笔友 | 其余所有情况（含陌生、通信中） | 否（无记录即非笔友） |

> 不再维护 STRANGER / CONTACTING / BONDED 等独立状态；"陌生""通信中""可添加笔友"全部由**信件往来记录派生**，仅用于 UI 展示（见 §10.3）。

### 10.3 展示态（UI 派生，非持久状态）

界面上的关系标签由"是否笔友 + 往来信件"实时推导：

| 展示态 | 判定条件 | 主要操作 |
|--------|----------|----------|
| 陌生 | 无往来信件、非笔友 | 写第一封信 |
| 通信中 | 有往来但未达添加阈值、非笔友 | 继续写信 |
| 可添加笔友 | 双向往来 ≥2 封、非笔友、无进行中申请 | 继续写信、添加笔友 |
| 申请中 | 存在待确认的笔友申请 | 等待确认 |
| 笔友 | 已是笔友 | 写信 |

### 10.4 笔友建立方式

**只有一种路径**：先通信，再申请，对方确认。

```
双向通信（≥2 封往来）→ 点击「添加笔友」→ 发送申请 → 对方在邮局确认 → 成为笔友
```

- **申请入口**：信箱前两个 Tab（收到/发出）中"可添加笔友"的信件项，或对方用户主页
- **确认入口**：邮局 → 关系消息 → 笔友请求 → `[同意] / [忽略]`

> **系统推荐不建立关系**：推荐只是把合适的人展示在"笔友页·推荐笔友"，用户仍需先写信通信、再走上面的申请流程。不存在"推荐一键成笔友"。

### 10.5 「添加笔友」按钮显示规则

本节仅定义 UI 何时显示 `[添加笔友]`，不涉及后端状态机。

| 条件（需同时满足） | 说明 |
|--------------------|------|
| 双向往来（A 发、B 回） | 至少一次有回复的通信 |
| 累计往来 ≥2 封 | 达到最小互动量 |
| 当前不是笔友 | 已是笔友则不显示 |
| 无进行中的笔友申请 | 申请中显示"等待确认" |

全部满足 → 显示 `[添加笔友]`；点击即发起申请（进入"申请中"），等待对方在邮局确认。

### 10.6 关系数据结构（参考）

只记录笔友关系与申请态；往来计数用于派生展示态：

```json
{
  "user_id": "",
  "target_user_id": "",
  "is_penpal": false,
  "penpal_request_status": "NONE | PENDING | ACCEPTED",
  "letter_count": 0,
  "first_contact_time": "",
  "penpal_time": ""
}
```

> 数据结构为参考，最终以实现为准；核心不变量：**无记录即非笔友**，展示态一律由往来信件实时推导。

## 11. 邮局消息系统（Post Office Message System）【新增】

### 11.1 系统定位

邮局是 **App 首页**，是「当前正在发生的事情」的聚合，也是**写信起点**。

面向 45+ 银发用户，首页遵循「**一屏一主张 + 详情点进去**」（详见 §12.8 适老化规范），只呈现：

1. **一句话状态**（顶部问候 + 今日关键提示）
2. **写信主按钮**（页面视觉中心，最大点击区）
3. **两张摘要卡**（只显示一句话 + 数字，点击展开明细）：
   - 关系消息摘要（笔友请求 + 关系提醒，计数）
   - 信件在途摘要（在路上 / 未读，合并计数）

> 注意：**系统推荐不在邮局消息中**。推荐的笔友只出现在「笔友 Tab → 推荐笔友」（§8.2 / §9）。

明细在 §11.3（关系消息）、§11.4（信件在途）定义，**点击摘要卡后进入**，不在首页平铺，避免过载。

职责分离：

- **邮局（首页）**：一句话状态 + 写信 + 关系消息摘要 + 在途摘要
- **信箱**：纯信件流水（收到的信 / 发出的信 / 时光信），**不含写信入口**

### 11.2 邮局首页结构

```
邮局（首页）
├── 一句话状态（问候 + 今日提示）
├── ✍️ 写信（大主按钮；提示今日免费额度，默认 5、配置驱动）
├── 摘要卡：📬 消息（N 条）›  →  点击进入明细（§11.3）
└── 摘要卡：✉️ 信件在途（N 封）›  →  点击进入明细（§11.4）
```

### 11.3 关系消息（明细，由首页摘要卡进入）

邮局关系消息只包含**笔友请求**与**关系提醒**两类（首页只显示条数摘要，点击进入本明细）。

> **系统推荐不在此处**：系统推荐的笔友统一在「笔友 Tab → 推荐笔友」呈现（§8.2 / §9），邮局不再有"系统推荐"消息。

**类型 1 · 笔友请求**（对方向你发起的申请，需你确认）：

```
--------------------------------
Tom 请求成为你的笔友
你们已经通信：5 封
[同意]  [忽略]
--------------------------------
```

- **同意**：对方 `PENDING → 笔友`，双方建立笔友关系
- **忽略**：申请失效，双方仍为非笔友（可继续通信）

**类型 2 · 关系提醒**（达到添加阈值后的提示，引导你发起申请）：

```
--------------------------------
你和 Tom 已经通信 5 封
可以添加为笔友啦
[添加笔友]
--------------------------------
```

- **添加笔友**：发起申请（进入"申请中"），等待对方在其邮局确认。

### 11.4 信件在途状态（明细，由首页摘要卡进入）

聚合"正在路上"的信件动态（首页只显示封数摘要，点击进入本明细）：

- **发出未达**：你的信正在路上（含预计到达时间）
- **收到未达**：有信正在向你送来（还未到达）
- **未读**：已送达但未阅读的信

**对端展示（适老化，禁止技术占位）**：

- 已匹配到具体用户：展示对方昵称
- **尚未匹配收件人**（POST_OFFICE 池中 / `to_user` 为空）：展示友好文案 **「推荐中」**（本地化可对应 *Finding a friend*）
- **禁止**向用户展示 `?`、`unknown`、`User`、以及「邮局匹配 / 邮局匹配池」等实现向文案
- 读信/在途详情**不单独展示**「模式：邮局匹配」一行；投递状态用状态芯片表达（在途 / 已达等）

```
--------------------------------
📤 推荐中 · 预计约 X 小时后到达     ← 未配对发出
📤 你写给 Anna 的信正在路上 · 预计 2 天后到达
📥 有 1 封信正在向你送来
📬 3 封已送达未读
--------------------------------
```

### 11.5 写信入口

邮局（首页）提供写信起点，展示**今日免费发送额度**。

- 每日赠送免费额度（默认 5 封/天，**数值由管理后台配置驱动**，见 §15.4）；用完当日不可再发
- 付费邮票（可购买额度）后续再定，本期不做
- 除额度外暂不展示其他辅助信息

**写信分流**：点击「写信」后二选一（大按钮，适老化）：

- **寄给有缘人**：不指定收件人，系统帮你找笔友（POST_OFFICE，§4.2）
- **寄给未来的自己**：时光信（SELF_TIME，§4.2），设置开启时间

> DIRECT（指定某人）不从此处发起，而是在对方主页 / 笔友页 / 信箱回信处点"写信 / 回信"进入（§4.2）。**时光信入口只此一处**，信箱仍不含写入口。

### 11.6 推送通知

关键事件通过 **系统推送 + 应用内红点/角标** 双通道触达，具体触发点复用 §5.3 信件事件流与关系事件。

| 事件 | 推送 | 应用内提醒位置 |
|------|------|----------------|
| 信件送达对方 | 可选 | 信件在途状态更新 |
| 收到新信（送达） | ✔ | 邮局在途 + 信箱红点 |
| 收到笔友请求 | ✔ | 邮局关系消息红点 |
| 笔友请求被同意 | ✔ | 邮局关系消息 |
| 系统推荐笔友 | 可选（低频） | 笔友页·推荐笔友（不进邮局消息） |
| 时光信开启 | ✔ | 信箱时光信 Tab |
| 信件审核未通过 | ✔ | 邮局在途 / 信箱发出（标注"未送达·退还额度"） |

- 用户可在「设置 → 通知设置」按类型开关（见 §13）
- 推送为体验增强，不改变信件/关系的落库与状态

### 12.6 读信页（开信）

用户点击「未读信件」（邮局在途未读 / 信箱收到）进入读信页，承载**开信仪式**（§5.4）。

```
+----------------------------------+
|  ‹ 返回                        ⋯ |   ← ⋯ = 举报 / 拉黑
+----------------------------------+
|        [ 邮戳：加拿大→中国 ]       |
|        寄出 07-06 · 已达 07-08     |
+----------------------------------+
|  来自 Anna                        |
|                                  |
|  今天阳光很好，希望你也一样……      |   ← 正文（拆封动画后分段展开）
|                                  |
|  [图片]                          |
+----------------------------------+
|   [   回  信   ]                  |   ← 主行动
|   （满足条件时）[ 添加笔友 ]        |
+----------------------------------+
```

- **进入即"开信"**：拆封动画 + 邮戳 + 正文分段展开（§5.4）
- **主行动**：仅收件人可见 **`[回信]`**（§4.7，进入写信桌）；满足 §10.5 条件时显示 `[添加笔友]`
- **发件人打开自己发出的信**：无回信区（不出现草稿输入框 / 置灰发送按钮）
- **对端未定时**：标题区展示「推荐中」，不用 `unknown` / `?`（§11.4）
- **⋯ 更多**：举报 / 拉黑（§15）
- **状态**：进入即置 `READ`（§4.3），发信人可在"发出的信"看到已读
- **时光信**：到点开启后同样在此页阅读，仅正文 + 时间，无回信/关系操作

### 12.7 空状态与冷启动

各页面首次/无数据时需给出引导，避免"白屏"：

| 页面 | 空状态 | 引导 |
|------|--------|------|
| 邮局 | 无消息 / 无在途 | 突出「写信」，提示"写下第一封信，等待有缘人" |
| 笔友页·推荐笔友 | 冷启动无候选 | 展示保护池/热门候选，提示"稍后有更多推荐" |
| 笔友页·我的笔友 | 暂无笔友 | 引导去"推荐/找笔友"写信 |
| 信箱-收到 | 暂无来信 | 提示"寄出的信正在路上，回信会出现在这里" |
| 信箱-时光信 | 暂无 | 引导写第一封时光信 |

新用户首启动衔接新手引导（§2.8）。

### 12.8 适老化与无障碍设计规范（全局约束）

面向 45+ 银发用户，以下为所有 UI 的**强制约束**，优先级高于视觉美观：

**信息密度**

- **一屏一主张**：每屏聚焦一个主任务/主行动；多条信息折叠为摘要卡，点击进入明细
- 首页等聚合页禁止平铺多组带按钮的列表（见 §11 首页）

**字号与文本**

- 正文字号下限约 17–18pt，关键信息更大；支持跟随系统"更大字体"
- 文案口语化、短句、避免专业黑话（如"发现"改"笔友"）；一句话说清一件事

**触控与布局**

- 可点击元素触控区 ≥ 48×48dp，按钮间留足间距，防误触
- 主行动用**大按钮**（写信等），次要操作弱化
- 图标必须**配文字标签**（老人对纯图标识别差）

**对比度与色彩**

- 文本对比度符合 WCAG AA（正文 ≥ 4.5:1）
- 不用低对比灰字传递关键信息；不单靠颜色区分状态（配图标/文字）

**反馈与容错**

- 每个操作有明确反馈（Toast/loading/成功态）
- 破坏性操作（拉黑/注销/删除）二次确认，文案直白
- 网络异常、空状态给出可读引导（见 §12.7）

**其他**

- 关键流程步骤尽量少、线性推进（如新手引导 §2.8）
- 支持无障碍朗读（TalkBack/VoiceOver）基础语义标签

> 具体数值（字号/触控/对比度阈值）作为前端设计规范落地项，可在实现阶段细化。

## 15. 风控系统（Safety System）

### 15.1 黑名单

功能，用户可以：

- 拉黑用户
- 查看黑名单
- 解除拉黑

影响，被拉黑用户：

- 无法发送信件
- 不进入推荐
- 无法申请笔友

### 15.2 举报系统

举报类型：

- 骚扰
- 诈骗
- 广告
- 不当内容
- 冒充身份
- 其他

流程：

```
用户举报 → 风险审核 → 处理结果
```

### 15.3 屏蔽系统

区别：

- **拉黑**：永久关系隔离
- **屏蔽**：隐藏内容

例如，用户可以：

- 不看某类推荐
- 不接收陌生信件

### 15.4 发送限制

限制：

- 每日发送额度
- 新用户发送保护
- 异常频率限制

额度规则：

- 每日赠送免费发送额度（默认 5 封/天，**数值由管理后台配置驱动**）
- 用完当日不可再发
- 付费邮票（可购买额度）后续再定，本期不做

额度边界：

- **计入额度**：面向他人的发信——POST_OFFICE、DIRECT，**写信与回信均计入**
- **不计入额度**：时光信（SELF_TIME，寄给自己）
- **重置**：按用户所在时区每日 0 点重置
- **前置拦截**（敏感词命中）：未发送，不扣额度
- **审核拒绝**：已扣额度退还；投递失败同样退还

限制目的，防止：

- 垃圾邮件
- 批量营销
- 骚扰行为

### 15.5 新用户保护池

规则：新用户前 3 封信

- **提高**：匹配质量、回复概率
- **降低**：无回复体验

### 15.6 内容安全与审核

1 对 1 私信采用「敏感词前置 + 默认放行 + 审核拦截」策略，恰好利用慢邮件的在途延迟窗口完成审核：

- **前置（英语敏感词）**：发送前对正文做英语敏感词检测，命中即拦截——**不发送、不扣额度**（敏感词库由管理后台配置）
- **默认放行**：通过前置的信标记为「待审核」但**照常进入投递**（发送成功），不阻塞在途体验
- **审核 + 举报**：信件在途/送达期间由机审 + 举报（§15.2）驱动审核
- **审核拒绝**：判定违规则**中止投递 / 撤回，不再送达**，退还额度，并按 §2.6 升级处置
- **图片附件**：机审（涉黄 / 暴恐 / 违规），阈值由管理后台配置
- **风险提示**：识别联系方式、诈骗话术等给予提示

> 采用"默认发、审核拦"而非"先审后发"：既保留"寄出即在路上"的仪式体验，又用在途延迟窗口完成审核；被拒绝的信在送达前拦下。

## 17. 核心闭环（Core Loop）

### 17.1 用户成长闭环

```
发现用户 → 发送第一封信 → 等待投递 → 收到回复 → 持续通信
        → 申请成为笔友 → 长期交流 → 行为反馈 → 优化推荐
```

### 17.2 用户关系闭环

```
陌生用户 → 通信对象 → 可添加笔友 → 笔友
```

### 17.3 产品核心原则

- **原则 1**：信件是核心交互，不是聊天。
- **原则 2**：关系来自通信，不是简单关注。
- **原则 3**：结构分工（底部四 Tab：邮局 / 笔友 / 信箱 / 我的）：
  - **邮局（首页）**：一句话状态 + 写信主按钮 + 关系消息摘要 + 在途摘要（明细点进）
  - **笔友**：找新笔友 + 管理笔友——推荐笔友 / 找笔友（筛选）/ 我的笔友
  - **信箱**：纯信件流水——收到的信 / 发出的信 / 时光信（不含写信入口）
  - **我的**：个人中心与设置
- **原则 4**：慢节奏是产品价值。避免：即时聊天、无限刷推荐、游戏化社交。
- **原则 5**：适老化优先。面向 45+，一屏一主张、大字大按钮、图文双标签、低密度（见 §12.8）。

### 20.2 管理后台配置项（config-driven）

以下参数统一在**管理后台**维护，不硬编码：

- 每日免费发送额度、额度重置时区策略
- 投递延迟区间（下限 / 抖动；上限固定 2 天）
- 匹配 Score 各项权重、分发比例（60 / 30 / 10）
- 收信每日上限、活跃判定窗口（默认 72h）
- 加笔友往来阈值（默认 ≥2）
- 英语敏感词库、图片机审阈值
- 正文长度上限、图片附件张数上限
- 时光信免费容量（默认 3 封）

### 20.3 / §21 管理后台运营（M7）

管理端（`senior-post-manage` / `/webapi`）在配置驱动之外，提供运营追踪能力：

**业务主体**

- 用户：多维筛选（邮箱/昵称/状态/性别/国家/年龄区间/VIP/头像审核/时间范围）、分页排序、批量改状态；编辑枚举一律下拉
- 信件：普通信件列表与审核（mode/status/auditStatus/关键词/时间）、详情预览与批量审核
- 笔友关系：分页查询、强制解除、往来封数
- 商业商品：类型/状态下拉、分页、批量上下架

**双轨邮件追踪**

- 系统出站邮件（`sys_mail_outbox`）：待发送/发送中/已发送/发送失败；详情预览 payload；失败可重试
- 用户信件：与信件运营同一模块，状态 Tag + 详情时间线

**通用**

- 列表统一分页/排序/批量；管理员操作写入 `log_admin_operation` 并可查询
- 看板：活跃用户/信件/待审/在途/今日新增/出站失败/笔友对数 + 近 7 日序列
- **不做**：CSV/Excel 等任何导入导出
