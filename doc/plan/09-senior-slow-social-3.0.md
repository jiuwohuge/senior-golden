# Senior Post 3.0 老年慢社交整改计划

> 版本：v0.3  
> 分支：feature_3.0  
> 日期：2026-06-03  
> 目标：把 Senior Post 从“功能型社交 App”收束为“面向中老年人的可信陌生笔友慢社交”。

---

## 1. 产品定位

### 1.1 一句话定位

**面向中老年人的可信陌生笔友慢社交：少打扰、重表达、慢建立、可纪念。**

### 1.2 目标用户

1. **退休后有表达需求的人**：愿意写经历、回忆、近况，但不想在公开广场被围观。
2. **想认识同龄朋友的人**：不追求即时匹配，而是希望通过话题、经历、书信慢慢认识。
3. **喜欢纪念和回忆的人**：愿意保存信件、老照片、时光信、笔友往来记录。
4. **需要更安心社交环境的人**：担心诈骗、骚扰、强打扰，希望平台主动保护。

### 1.3 不做什么

1. 不做强刺激陌生人速配。
2. 不做刷不完的信息流。
3. 不把 IM 聊天作为第一主场。
4. 不把邮票/VIP 做成强游戏货币。
5. 不把公开广场作为唯一增长入口。
6. 不把产品主线做成子女关怀、家庭看护或家属管理。
7. 不做假用户、假来信、假评论、假聊天记录。

## 2. 当前主要问题

| 问题 | 影响 | 3.0 改法 |
|---|---|---|
| 功能过多，入口分散 | 新用户不知道每天打开要做什么 | 首页收束为“今日信箱 + 等待中的信 + 推荐主题信箱” |
| 陌生人社交信任成本高 | 老年用户担心诈骗、骚扰、情感操控 | 建立安全分层、反诈提示、陌生人限制、人工复核 |
| 时光信/慢信件特色不够居中 | 核心差异被普通社交功能稀释 | 将“写信、等待、回信、纪念”提升为主链路 |
| 管理后台偏运营通用 | 缺少围绕老人安全与关系质量的工具 | 增加高风险会话、反诈关键词、风险信件、关系质量看板 |
| 付费点偏通用 VIP/邮票 | 容易削弱信任感 | 转向纪念、实体、安心服务、高质量推荐、主题增值 |
| 老年友好不足 | 学习成本高、误触风险高 | 大字模式、语音输入/朗读、一步一屏、弱化术语 |
| 冷启动早期内容不足 | 新用户进来空、写出去无人回应 | 用官方主题、官方来信、透明 AI 小助手、定时内容任务兜底 |

## 3. 核心竞争力设计

### 3.1 核心竞争力

**可信慢关系。**

不是“认识更多人”，而是让用户在一个安全、低压力、有仪式感的环境里，愿意表达、愿意等待、愿意回信，并逐渐形成稳定关系。

### 3.2 体验主张

1. **慢**：信件不是秒回工具，系统鼓励认真表达。
2. **稳**：关系建立有门槛、有节奏、有保护。
3. **暖**：产品像邮局和纪念册，不像娱乐平台。
4. **可信**：对诈骗、骚扰、敏感信息有主动防护。
5. **可留存**：每封信、每段关系都能沉淀为纪念。

### 3.3 3.0 北极星指标

北极星指标：**每周有效通信用户数**。  
定义：一周内至少完成一次读信、写信、回信、收藏或打开时光信的用户数。

停留时间只作为辅助观察，不作为核心增长目标。短停留但完成读信、写信、回信、收藏，是符合慢社交定位的健康行为。

| 指标 | 定义 | 目的 |
|---|---|---|
| 首次写信率 | 新用户注册后 24 小时内写出第一封信 | 验证第一体验是否成立 |
| 7 日回信率 | 新用户 7 天内至少完成 1 次回信 | 验证慢关系是否成立 |
| 有效信件率 | 正文长度、非灌水、非违规的信件占比 | 验证表达质量 |
| 安全拦截成功率 | 风险内容被提示/拦截/复核的比例 | 验证可信环境 |
| 30 日稳定笔友数 | 30 天内互通信件达到阈值的关系数 | 验证关系沉淀 |
| 纪念付费转化率 | 纪念册、实体明信片、信纸邮戳、安心会员转化 | 验证自然盈利能力 |

## 4. 信息架构整改

### 4.1 App 主导航建议

| 当前能力 | 3.0 导航 | 说明 |
|---|---|---|
| 明信片墙 | 主题信箱 | 由公开信息流改为主题投稿/阅读，降低陌生人压力 |

### 4.2 首页第一屏

首页不做营销页，直接进入可用体验：

1. 今日收到的信。
2. 等待送达的信。
3. 今日推荐主题信箱。
4. 一个主按钮：写一封信。
5. 一个辅助按钮：听信/语音写信。

## 5. UI/UX 设计规划

### 5.1 设计目标

3.0 的 UI 目标不是“年轻化、酷、停留久”，而是：

1. **看得清**：默认字号更大、对比更高、行距更松。
2. **点得准**：触控目标足够大，关键按钮不拥挤。
3. **走得明白**：每个页面只突出一个主任务。
4. **不焦虑**：不使用红点轰炸、倒计时催促、强运营弹窗。
5. **有邮局感**：温和、可信、有仪式感，但不做复杂装饰。

### 5.2 视觉风格

| 项 | 规范 |
|---|---|
| 整体气质 | 温和、安静、可信，接近“邮局 + 纪念册”，避免短视频/游戏化风格 |
| 色彩 | 使用暖白/浅纸色作为背景，搭配邮政绿、深墨色、柔和朱红作强调；避免大面积高饱和渐变 |
| 字体 | 使用系统字体，支持系统字体缩放；正文默认不小于 17sp，大字模式不小于 20sp |
| 圆角 | 卡片和按钮控制在 8px 左右，避免过度圆润和儿童化 |
| 图标 | 使用统一线性图标风格；按钮中优先用清晰图标 + 文案，不使用表情符号当功能图标 |
| 插图 | 用于空状态、欢迎信、纪念册；不遮挡正文，不喧宾夺主 |

### 5.3 布局与导航

1. 底部导航控制在 4 个主入口：主题信箱、笔友、我的信箱、纪念册。
2. 首页第一屏必须直接展示“来信/等待/主题/写信”，不做营销式 Hero。
3. 列表项保持稳定高度和清晰分隔，避免密集信息墙。
4. 写信流程采用一步一屏：选对象 -> 写内容 -> 选择投递/主题 -> 确认。
5. 每个页面只保留一个主按钮，其他动作弱化为次级按钮或菜单。
6. 返回路径必须清晰，不依赖隐藏手势完成关键操作。

### 5.4 适老交互

| 场景 | 规范 |
|---|---|
| 点击区域 | 主要按钮和图标热区不小于 48dp，按钮间距不小于 8dp |
| 表单 | 所有输入框必须有可见标签，不能只靠 placeholder |
| 错误提示 | 错误显示在对应字段附近，文案直接说明怎么改 |
| 加载状态 | 超过 300ms 展示加载反馈；超过 1s 使用骨架或明确进度 |
| 危险操作 | 删除、举报、拉黑、付费前必须二次确认 |
| 动效 | 只用于状态变化和层级过渡；尊重系统减少动态效果设置 |
| 语音 | 写信页预留语音输入；阅读页预留朗读入口 |
| 无障碍 | 支持屏幕阅读器顺序、语义标签、颜色不作为唯一状态表达 |

### 5.5 关键组件清单

| 组件 | 用途 |
|---|---|
| `SeniorBottomNav` | 4 个主入口，支持大字和清晰选中态 |
| `TodayMailboxPanel` | 首页今日来信、等待中、草稿、主题入口 |
| `LetterCard` | 信件列表项，展示发信人、主题、状态、时间 |
| `TopicMailboxCard` | 主题信箱入口，展示主题名、导语、今日投稿数 |
| `ComposeStepScaffold` | 写信一步一屏流程容器 |
| `SafetyNotice` | 反诈、隐私、陌生人提醒 |
| `PostalAssistantEntry` | 透明 AI 邮局小助手入口，必须标注 AI 身份 |
| `MemorialEntryCard` | 纪念册条目，展示收藏信件、时光信、笔友纪念 |
| `LargeTextToggle` | 大字模式开关 |

### 5.6 UI 验收标准

1. 60 岁以上用户无需教学，可以在 3 分钟内完成第一封信。
2. 普通模式和大字模式下，主要按钮和正文不重叠、不截断。
3. 所有核心流程在 375px 宽度手机上无横向滚动。
4. 主要文本对比度满足可读性要求。
5. 红点、推送、弹窗不制造焦虑；提醒可关闭或降频。
6. 付费入口不遮挡基础写信流程。
7. AI 小助手入口与真人笔友入口视觉上必须明显区分。

## 7. 付费体系建议

### 7.1 付费原则

1. **基础写信不能被强付费卡住。**
2. **付费买的是纪念、安心、实体和便利，不买社交优先权。**
3. **避免制造焦虑和攀比。**
4. **购买者以老人本人为主，可保留子女代付，但不把家庭陪伴作为核心叙事。**

### 7.2 付费产品矩阵

| 产品 | 目标购买者 | 价值 | 备注 |
|---|---|---|---|
| 安心会员 | 用户本人 | 反诈增强提醒、语音转写、朗读、优先客服、长信存档 | 不应和“陌生人曝光”绑定 |
| 数字纪念册 Pro | 用户本人 | 长期保存、年度回忆、关系纪念页、导出 PDF | 最自然的订阅点 |
| 实体明信片/实体信件 | 用户本人 | 把 App 内容变成真实纪念或真实投递 | 单次付费，低门槛 |
| 高质量笔友推荐 | 用户本人 | 更细筛选、更安全、更少量的精选推荐 | 不能卖无限曝光 |
| 主题信箱会员 | 用户本人 | 高级主题、主题纪念册、精选投稿沉淀 | 围绕主题价值付费 |
| 纪念信封/邮戳 | 用户 | 仪式感装饰 | 小额付费 |
| 子女代付/安心联系人 | 可选辅助 | 代付会员或接收高风险安全提醒 | 后期辅助能力，不做主线 |

### 7.3 商业化实施顺序

1. **第一期**：数字纪念册 Pro + 安心会员 + 纪念信纸/邮戳。
2. **第二期**：实体明信片/实体信件，等真实留存和用户付费意愿初步验证后再做。
3. **第三期**：高质量笔友推荐和主题信箱会员，等安全、推荐和主题内容数据稳定后再做。
4. 子女代付/安心联系人只作为辅助能力，不进入首个商业化版本。

### 7.4 不建议的付费点

1. 付费解锁陌生人更多曝光。
2. 付费跳过安全审核。
3. 付费无限私聊陌生人。
4. 过度游戏化抽卡、盲盒、排行榜。
5. 高压式连续包月弹窗。
6. 把家庭看护、子女监护、亲情陪伴作为核心商业主线。

## 8. 冷启动方案

### 8.1 冷启动目标

早期不要制造虚假繁荣，而是降低用户第一次表达的孤独感：

1. 用户进来有内容可读。
2. 用户知道今天可以写什么。
3. 用户写第一封信时不迷茫。
4. 用户没有真人回应时，也能获得明确、透明、不伪装的陪伴和引导。

### 8.2 不采用真实种子用户池

考虑到当前是个人开发者项目，不把“真实种子笔友池、志愿者回复、人工运营大量分发”作为 3.0 必需能力。

原因：

1. 运营成本高，长期不可持续。
2. 回复质量不可控。
3. 容易把开发重心从产品机制转向人工运营。

### 8.3 官方每日主题信箱

系统每天自动生成或从配置池中轮换 3-5 个主题，作为用户写信入口。

示例主题：

1. 记忆里的故乡。
2. 退休后最自在的一天。
3. 一张老照片背后的故事。
4. 你最怀念的一顿饭。
5. 想对同龄笔友说的一句话。
6. 最近想认识什么样的笔友。

验收标准：

1. 每天至少有 1 个主题可写。
2. 主题可后台配置、启停、排序。
3. 主题页可以展示官方导语和真实用户投稿。
4. 没有真实投稿时，可以展示官方示例信，但必须标注“官方示例”。

### 8.4 官方邮局来信

新用户注册、首次写信、首次等待回信等关键节点，可以收到官方来信。

官方来信类型：

1. 欢迎信。
2. 第一封信引导。
3. 安全提醒信。
4. 时光信引导。
5. 节日问候。
6. 长时间未写信后的温和提醒。

要求：

1. 发信身份必须是“官方邮局”或类似明确身份。
2. 不伪装成普通用户。
3. 不制造“有人暗恋你、有人等你”等焦虑式话术。
4. 可以关闭或减少提醒频率。

### 8.5 透明 AI 邮局小助手

可以对接 AI，做一个明确身份的“邮局小助手”。

实施顺序：AI 小助手放第二批。第一期先用官方每日主题和官方邮局来信完成基础冷启动，避免过早引入 AI 成本、审核边界和安全风险。

适合能力：

1. 帮用户想写信主题。
2. 帮用户润色文字。
3. 帮用户把语音整理成信件。
4. 解释如何安全认识笔友。
5. 在无人回应时，提供练习型、陪伴型写信体验。

边界：

1. 必须明确标注这是 AI/小助手。
2. 不伪装成真人笔友。
3. 不主动索要隐私、联系方式、钱款相关信息。
4. 高风险内容触发安全提示，而不是继续推进对话。

### 8.6 自动内容任务

可以定时生成：

1. 今日主题。
2. 官方导语。
3. 写信提示。
4. 节日问候。
5. 安全提醒。
6. 时光信提示。
7. 纪念册回顾文案。

禁止自动生成：

1. 假用户资料。
2. 假来信。
3. 假回信。
4. 假评论。
5. 假聊天记录。
6. 假点赞或假热度。

### 8.7 冷启动退场条件

官方内容不需要完全停止，但应该从“主供给”逐步变成“辅助引导”。

可观察门槛：

1. 每日真实有效信件数达到稳定阈值。
2. 主题信箱真实投稿占比超过 70%。
3. 新用户 7 日回信率稳定提升。
4. 用户首封信平均等待回应时间进入可接受区间。
5. 官方来信点击率下降但真实互动上升。

## 9. 阶段路线图

### M1：产品收束原型

目标：把主链路从“社交功能集合”改成“信件陪伴”。

交付：
1. 新 IA 与主导航方案。
2. 今日信箱首页原型。
3. 写信入口重构方案。
4. 旧功能迁移映射表。
5. 冷启动内容池与官方身份规则。
6. UI/UX 设计规范与核心组件清单。

### M2：可用 MVP

目标：让用户完成“写信 -> 等待 -> 收信 -> 回信 -> 纪念”的闭环。

交付：
1. 今日信箱。
2. 主题信箱基础版。
3. 笔友推荐基础版。
4. 时光信并入信箱主链路。
5. 大字模式。
6. 官方每日主题与官方邮局来信。
7. 不接 AI 的基础冷启动闭环。

### M3：安全可信版

目标：解决老年陌生人社交最关键的信任问题。

交付：
1. 反诈话术规则。
2. 风险信件队列。
3. 陌生人私聊限制。
4. 安心联系人。
5. 后台安全看板。
6. 透明 AI 邮局小助手（第二批，不进入首个 MVP）。

### M4：商业化版

目标：上线不破坏信任的自然盈利点。

交付：
1. 数字纪念册 Pro。
2. 安心会员。
3. 纪念信纸/邮戳。
4. 实体明信片订单（真实留存后再启动）。
5. 高质量笔友推荐（安全和推荐数据稳定后再启动）。
6. 主题信箱会员。
7. 订单与履约后台。

### M5：增长与质量优化

目标：提升回信率、稳定笔友关系、降低风险。

交付：
1. 笔友推荐算法优化。
2. 主题运营工具。
3. 官方内容任务自动化优化。
4. 数据看板与 A/B 实验。

## 12. 成功验收

3.0 不以“功能更多”为成功标准，而以以下结果验收：

1. 新用户第一次打开能明确知道：这是一个写信和收信的慢陪伴产品。
2. 老年用户不依赖教学，也能完成写信、收信、回信。
3. 陌生人骚扰和诈骗风险有主动防护，而不是只靠事后举报。
4. 时光信、慢信件、纪念册形成产品记忆点。
5. 付费点不破坏信任，且至少形成一个可测试商业闭环。
6. 冷启动内容能帮助新用户完成第一封信，但不依赖假用户假互动。
7. AI 能力透明可识别，不伪装成真人笔友。
