# Senior Post 3.0 老年慢社交整改计划

> 版本：v0.1  
> 分支：feature_3.0  
> 日期：2026-06-03  
> 目标：把 Senior Post 从“功能型社交 App”收束为“给中老年人的可信慢信件陪伴社区”。

---

## 1. 产品定位

### 1.1 一句话定位

**给中老年人的慢信件陪伴社区：少打扰、重表达、可信任、有纪念感。**

### 1.2 目标用户

1. **退休后有表达需求的人**：愿意写经历、回忆、近况，但不想在公开广场被围观。
2. **空巢或异地家庭关系用户**：希望有一个更温和的方式和家人、朋友保持联系。
3. **想认识同龄朋友的人**：不追求即时匹配，而是希望通过话题、经历、书信慢慢认识。
4. **子女/家属协助型用户**：家属可能帮助注册、设置安全项、购买纪念服务。

### 1.3 不做什么

1. 不做强刺激陌生人速配。
2. 不做刷不完的信息流。
3. 不把 IM 聊天作为第一主场。
4. 不把邮票/VIP 做成强游戏货币。
5. 不把公开广场作为唯一增长入口。

---

## 2. 当前主要问题

| 问题 | 影响 | 3.0 改法 |
|---|---|---|
| 功能过多，入口分散 | 新用户不知道每天打开要做什么 | 首页收束为“今日信箱 + 等待中的信 + 推荐主题信箱” |
| 陌生人社交信任成本高 | 老年用户担心诈骗、骚扰、情感操控 | 建立安全分层、反诈提示、陌生人限制、人工复核 |
| 时光信/慢信件特色不够居中 | 核心差异被普通社交功能稀释 | 将“写信、等待、回信、纪念”提升为主链路 |
| 管理后台偏运营通用 | 缺少围绕老人安全与陪伴的运营工具 | 增加高风险会话、反诈关键词、家属安全协助、陪伴质量看板 |
| 付费点偏通用 VIP/邮票 | 容易削弱信任感 | 转向纪念、实体、家庭、安心服务等自然付费 |
| 老年友好不足 | 学习成本高、误触风险高 | 大字模式、语音输入/朗读、一步一屏、弱化术语 |

## 3. 核心竞争力设计

### 3.1 核心竞争力

**可信慢关系。**

不是“认识更多人”，而是让用户在一个安全、低压力、有仪式感的环境里，愿意表达、愿意等待、愿意回信，并逐渐形成稳定关系。

### 3.2 体验主张

1. **慢**：信件不是秒回工具，系统鼓励认真表达。
2. **稳**：关系建立有门槛、有节奏、有保护。
3. **暖**：产品像邮局和纪念册，不像娱乐平台。
4. **可信**：对诈骗、骚扰、敏感信息有主动防护。
5. **可留存**：每封信、每段关系都能沉淀为纪念。

### 3.3 3.0 北极星指标

| 指标 | 定义 | 目的 |
|---|---|---|
| 7 日回信率 | 新用户 7 天内至少完成 1 次回信 | 验证慢关系是否成立 |
| 有效信件率 | 正文长度、非灌水、非违规的信件占比 | 验证表达质量 |
| 安全拦截成功率 | 风险内容被提示/拦截/复核的比例 | 验证可信环境 |
| 30 日稳定笔友数 | 30 天内互通信件达到阈值的关系数 | 验证关系沉淀 |
| 纪念付费转化率 | 纪念册、实体明信片、家庭服务转化 | 验证自然盈利能力 |

## 4. 信息架构整改

### 4.1 App 主导航建议

| 当前能力 | 3.0 导航 | 说明 |
|---|---|---|
| 明信片墙 | 主题信箱 | 由公开信息流改为主题投稿/阅读，降低陌生人压力 |
| 名录 | 笔友推荐 | 每日少量推荐，强调适配与安全 |
| 邮政信箱 + 时光信 | 我的信箱 | 收件、寄件、等待、时光信统一 |
| 聊天 | 关系内私聊 | 不作为主入口，必须由信件关系或安全门槛解锁 |
| 个人中心 | 我的纪念册 | 资料、邮票、纪念、设置、安全合并 |

### 4.2 首页第一屏

首页不做营销页，直接进入可用体验：

1. 今日收到的信。
2. 等待送达的信。
3. 今日推荐主题信箱。
4. 一个主按钮：写一封信。
5. 一个辅助按钮：听信/语音写信。

## 6. 付费体系建议

### 6.1 付费原则

1. **基础写信不能被强付费卡住。**
2. **付费买的是纪念、安心、实体和便利，不买社交优先权。**
3. **避免制造焦虑和攀比。**
4. **价格体系要适合子女代付。**

### 6.2 付费产品矩阵

| 产品 | 目标购买者 | 价值 | 备注 |
|---|---|---|---|
| 数字纪念册 Pro | 用户/子女 | 长期保存、年度回忆、导出 PDF | 最自然的订阅点 |
| 家庭陪伴月卡 | 子女 | 家属安全联系人、关怀提醒、纪念册共享 | 注意隐私边界 |
| 实体明信片 | 用户/子女 | 把 App 内容变成真实纪念 | 单次付费，低门槛 |
| 纪念信封/邮戳 | 用户 | 仪式感装饰 | 小额付费 |
| 安心会员 | 用户/子女 | 语音转写、朗读、优先客服、安全提醒增强 | 不应和“陌生人曝光”绑定 |

### 6.3 不建议的付费点

1. 付费解锁陌生人更多曝光。
2. 付费跳过安全审核。
3. 付费无限私聊陌生人。
4. 过度游戏化抽卡、盲盒、排行榜。
5. 高压式连续包月弹窗。

## 7. 阶段路线图

### M1：产品收束原型

目标：把主链路从“社交功能集合”改成“信件陪伴”。

交付：
1. 新 IA 与主导航方案。
2. 今日信箱首页原型。
3. 写信入口重构方案。
4. 旧功能迁移映射表。

### M2：可用 MVP

目标：让用户完成“写信 -> 等待 -> 收信 -> 回信 -> 纪念”的闭环。

交付：
1. 今日信箱。
2. 主题信箱基础版。
3. 笔友推荐基础版。
4. 时光信并入信箱主链路。
5. 大字模式。

### M3：安全可信版

目标：解决老年陌生人社交最关键的信任问题。

交付：
1. 反诈话术规则。
2. 风险信件队列。
3. 陌生人私聊限制。
4. 安全联系人。
5. 后台安全看板。

### M4：商业化版

目标：上线不破坏信任的自然盈利点。

交付：
1. 数字纪念册 Pro。
2. 实体明信片订单。
3. 家庭陪伴月卡。
4. 安心会员。
5. 订单与履约后台。

### M5：增长与质量优化

目标：提升回信率、稳定笔友关系、降低风险。

交付：
1. 笔友推荐算法优化。
2. 主题运营工具。
3. 沉默用户温和召回。
4. 数据看板与 A/B 实验。

## 10. 成功验收

3.0 不以“功能更多”为成功标准，而以以下结果验收：

1. 新用户第一次打开能明确知道：这是一个写信和收信的慢陪伴产品。
2. 老年用户不依赖教学，也能完成写信、收信、回信。
3. 陌生人骚扰和诈骗风险有主动防护，而不是只靠事后举报。
4. 时光信、慢信件、纪念册形成产品记忆点。
5. 付费点不破坏信任，且至少形成一个可测试商业闭环。
