## 0. 已定观点（作者已认同 · 2026-08-12）

以下条目视为**产品宪法**，后续需求以此筛查；冲突则改需求，不改宪法（除非作者显式推翻）。

### 0.1 作者边界

| 项 | 已定 |
|----|------|
| 身份 | 独立开发，低维护成本 |
| 获客 | 不重投放、不地推、不实体邮寄履约 |
| 阶段 | 先留存 / 回访 / 愿意写愿意等；付费后置；只赚小钱 |
| 规模 | **小而精**，不做准社交平台 |

### 0.2 定位与主路径

| 项 | 已定 |
|----|------|
| 显示名 | **时光邮局**（作者拍板；「慢」是体验属性，不必进品牌名。阶段 2 用户间通信仍可沿用此名） |
| 一句话 | 时光邮局：寄给未来的自己；封缄 → 在途 → 拆封；可分享慢信卡片 |
| 主路径 | **时光信（写给自己）** — 阶段 1 唯一主推 |
| 支线 | **寄往邮局保留**；下拉/默认优先时光信；文案降预期；首弹不推邮局 |
| 阶段 1 不可见 | **无**找笔友 Tab、**无**推荐、**无**匹配加重露出（隐藏） |
| 阶段 2 | 留存与池密度够了之后，再打开用户间通信相关入口 — 届时另议 |
| 鉴权 | **静默可用**（设备身份先进来）；**注册/绑定后置**（非取消）；**登录保留**（换机/清数据后，已绑定账号可登回） |
| 不是什么 | 不是日记、不是交友 App、不是会员商店 |

### 0.3 对抗日记 / 胶囊的差异化钉

| 项 | 已定 |
|----|------|
| 话术 | **禁用**日记 / 记录 / 笔记等对外文案；统一写信、封缄、投递、在途、拆封、邮筒、邮戳 |
| 寄出锁定 | **时光信寄出后不可读全文，仅可看信封/在途信息，到达后拆封才读**（对抗日记的关键机制） |
| 双峰值 | 封缄（寄出）与拆封（到达）对称；推送进 App 须先拆封再露正文 |
| 在途 | 一等公民：可回访、有邮局感、可分享「还在路上的信」 |
| 品牌四件套 | **封缄 / 在途 / 拆封 / 慢信卡片** — 缺一则差异化塌 |

### 0.4 窄品类与增长

| 项 | 已定 |
|----|------|
| 获客公式 | 到访转化 × 分享率 × 回访（拆封推送）；接受涓流，不幻想爆款 |
| 商店叙事 | 只讲一件事：寄给未来的自己 / 慢拆封；不并排交友、日记、AI、会员 |
| 指标 | 寄出率、在途回访、拆封率、分享率、周回访；**不用社交 DAU 衡量自己** |

### 0.5 筛查口诀（每个功能过一遍）

1. 是否服务「愿意写」或「愿意等」或「愿意分享带来下一用户」？  
2. 是否强化邮局四件套，而不是把它做成日记/社交？  
3. 独立开发是否维护得起？  
4. 人少时会不会社死或空转？  

任一题答「否」→ 进入 §3 争议清单讨论，默认倾向：**砍 / 藏 / 后置**。

## 1. 用户痛点（小而精只打这些）

| 痛点 | 用户内心 | 产品应答（只保留能打中的） |
|------|----------|---------------------------|
| 想说却写不出 | 「心里有事，落笔就干」 | 倾诉模板 + AI 润色/灵感（少而强） |
| 想给未来的自己留话 | 「怕忘了此刻的心情」 | 时光信主路径 + 下周/下月/90 天 |
| 即时回看太便宜、没有仪式 | 「写成日记就没感觉了」 | 寄出锁定 + 封缄/在途/拆封 |
| 想晒仪式又怕隐私 | 「想发朋友圈又不敢」 | 慢信卡片 + 隐段 + 脱敏 |
| 等的时候容易忘/卸载 | 「放着就忘了」 | 在途可回访 + 到达推送 |
| （弱）想碰运气寄给人 | 「有缘人看看也行」 | 邮局支线，不承诺速配 |

**明确不作为首发痛点**：找笔友、逛推荐、经营关系链、装扮收集、会员身份炫耀。

## 2. 核心闭环（定稿方向）

```text
静默进入 → 今日寄语 → 写给「下周的自己」（模板/AI 可选）
  → 封缄动画 → 在途可看可分享（不可读正文）
  → 到期推送 → 拆封 → 读信 → 再写一封或分享卡片
```

支线（不阻塞主闭环）：寄往邮局 / 笔友（隐藏入口）。

## 3. 功能治理清单（小而精审计）

> 图例：**保留** = 打痛点；**收敛** = 做瘦；**隐藏/后置** = 冷启动不做主路径；**建议砍或深藏** = 与宪法冲突或过重；**待讨论** = 需作者拍板。

### 3.1 建议保留（P0 骨架 · 仍不开工，仅定方向）

| 能力 | 理由 |
|------|------|
| 静默进入 + 注册/绑定后置 + 登录保留 | 打开即用；换机/清数据可凭已绑定账号登回；AI/付费时可要求绑定 |
| 三 Tab：邮局 / 信箱 / 我的 | 结构小 |
| 首弹：额度提示 + 今日语 +「写给下周自己」 | 愿意写的第一推动 |
| 时光信档位：下周 / 下月同日 / 90 天内自定义 | 愿意等的时间锚点 |
| 寄出锁定正文 | 差异化钉 |
| 封缄动画 + 拆封动画 | 双峰值 |
| 在途列表/详情（邮局感文案） | 愿意等 |
| 到达推送（文案池） | 回访闹钟 |
| AI：仅「润色」「灵感」两键 + 重做 prompt | 愿意写；五模式过肥 |
| 倾诉模板（少量 5–8，后台可配） | 愿意写 |
| 慢信卡片分享（长图优先）+ 脱敏/隐段 | 涓流获客 |
| 分享小奖励（严防刷，可关） | 促分享 |
| 删除旧商店/皮肤大商业入口 | 去肥 |

### 3.2 收敛后保留（支线或瘦身）

| 能力 | 处理 |
|------|------|
| 寄往邮局（POST_OFFICE） | **支线**：入口保留但文案降预期（「寻找有缘人，可能需要较久」） |
| 笔友关系 | **沉信箱**；找笔友 Tab **隐藏** |
| 每日发信额度 | 保留轻约束；别做成游戏货币体系 |
| 敏感词/审核/举报拉黑 | 保留底线安全；UI 少暴露术语 |
| 绑定邮箱/手机 + **登录入口** | 「我的」可绑可登；AI/付费前可引导绑定（防换机丢信）；**不是取消注册/登录** |

### 3.3 已批准砍、深藏或后置（开工时执行）

| 能力 | 问题 | 决定 |
|------|------|------|
| **找笔友 Tab / 每日推荐 / 复杂筛选** | 人少社死；像社交平台；冲淡邮局叙事 | **隐藏**（阶段 2 再议打开） |
| **旧邮政商店：皮肤/字体/模板大商城** | 不打「愿意写/等」；像收集游戏 | **删除或深藏**；免费默认信纸即可 |
| **VIP 身份包装 / 多 SKU 会员中心** | 信任门槛高 | **不做**；将来最多极简 AI 次数包 |
| **匹配 v2 / 行为中台复杂化** | 主路径已不是匹配 | **冻结**，别继续加分 |
| **信件导出/纪念册大功能** | 工程重；非首发 | **后置** |
| **图片附件** | 审核与存储成本 | **后置** |
| **语音/音乐明信片付费** | 工程重 | **后置**（P2） |
| **精准投递卡/寻音卡** | 冷启动无池无效 | **关闭** |
| **AI 五模式** | 选择过载 | **收敛为润色+灵感** |
| **注册全流程前置** | 与静默冲突 | **后置到 AI/付费/自愿** |
| **四 Tab 含笔友发现** | 过宽 | **改三 Tab：邮局/信箱/我的** |
| **管理后台继续堆业务页** | 一人维护不起 | **只留必要配置** |
| **同城/匹配当卖点宣传** | 易滑向交友 | **不宣传** |
| **「日记/记录」对外话术** | 差异化塌 | **禁用**，改邮局话术 |

### 3.4 付费点（与宪法对齐后的态度）

| 付费点 | 态度 |
|--------|------|
| AI 高级润色/灵感次数（寄过一封后露） | **唯一优先小钱点**；即时兑现 |
| 语音/音乐附件 | 后置 |
| 寻音卡 | 关闭 |
| 皮肤商城/VIP 大包 | 放弃作为主商业 |

## 5. 决策评估与拍板（截至 2026-08-13）

> 下方为评估过程与正式拍板。未写「开工」= 只锁定产品结论；实现另立工程计划。

### 5.1 评估（先评，再定）

#### 决策 1：建议砍/深藏的清单认同，允许执行

**评估：正确。**  
与 §0 宪法一致。此处「允许执行」理解为：**方向已批准，可写入定稿并在将来工程排期时执行**；不等于本轮立刻改代码（作者此前明确不急着做实现计划）。

**拍板：通过。** §3.3 清单列为「已批准砍/深藏」，开工时按该表执行。

---

#### 决策 2：寄往邮局保留；下拉优先时光信

**评估：正确，且比「完全隐藏邮局」更符合你对品牌的长期想象。**  
风险只有一个：若两个入口视觉权重一样，用户仍会点进空池。  
**必须加护栏**：默认选中/排序第一 = 时光信；邮局文案降预期（「寻找有缘人，可能需要较久」）；首弹 CTA 只推「写给下周的自己」，不推邮局。

**拍板：通过（带护栏）。** 邮局 = 支线入口保留；时光信 = 默认与优先。

---

#### 决策 3：分享做长图；有无技术卡点？

**评估：方向正确；无硬卡点，有工程成本。**  

现状：Flutter 工程**尚未**接入 `share_plus` / 截图导出类依赖（仅有 `shared_preferences`）。  
可行技术路径（常规）：

1. 用 `RepaintBoundary` 渲染「慢信卡片」Widget（信纸、邮戳、日期、正文/隐段、App 二维码）  
2. `toImage` → PNG  
3. `share_plus`（或系统分享）发出；可选再存相册  

| 卡点类型 | 说明 | 严重度 |
|----------|------|--------|
| 依赖与权限 | 需加分享/存图插件；Android/iOS 相册与分享权限 | 低，常规 |
| 长文排版 | 正文很长时需限高、缩字号、或「仅展示节选+隐段」 | 中，产品规则要先定 |
| 中文字体 | 卡片内嵌字体，避免分享到外机变方框 | 中，要选可商用字体 |
| 二维码 | 链到应用商店（分 iOS/Android 或落地页） | 低 |
| 脱敏 | 规则或轻量 AI；可先做「用户手选隐段」+ 简单正则（手机号等） | 中，可分两期 |
| H5 | 不做则避开服务端页与短链 | 已避开 |

**拍板：通过。首版只做长图，不做 H5。** 首版卡片策略：正文节选 + 可选手动隐段；正则脱敏可跟；AI 脱敏可二期。

---

#### 决策 4：今日寄语 AI 每日生成 + 避免短期重复

**评估：正确，但要比「文案池」贵一点（token），换新鲜感值得。**  

防重复可执行规则（建议写入配置）：

- 服务端保留近 **N 天**（建议 14 或 30）已下发寄语的 fingerprint（原文 hash 或 embedding 粗判）  
- 生成后若命中近 N 天相似 → 重试最多 2 次 → 仍重复则降级文案池兜底  
- 按 **用户维度** 去重（同一句可以给不同用户，但同一用户短期不重复）  
- 失败/超时时用本地/后台兜底句，保证首页不空白  

**拍板：通过。** AI 日更 + 用户维近 N 天去重 + 兜底池。

---

#### 决策 5（修订）：显示名用「时光邮局」；阶段 1 主推时光信；阶段 2 再开用户间通信

**作者补充：**  
- 「慢邮局」不好听 → **品牌维持「时光邮局」**。  
- 「以后再推用户通信」只是名字可延展；阶段 1 **无**找笔友 Tab / 推荐 / 匹配加重露出。

**评估：正确。**「时光邮局」与主路径时光信同构；「慢」用体验表达即可，不必塞进店名。

**拍板：通过。显示名 = 时光邮局。**

#### 决策 6（新增）：鉴权 = 静默可用，注册后置，登录保留

**作者澄清：** 注册不是取消，只是后置；登录必须保留，方便换机/清数据后用已绑定账号找回。

**评估：正确。** 正确模型：

\\\	ext
首次打开 → 设备静默身份 → 直接用主路径
需要 AI / 付费 / 自愿 → 引导注册或绑定
「我的」始终提供：绑定、登录
换机/清数据 → 走登录，恢复已绑定账号下的信与权益
\\\

**拍板：通过。**

#### 决策 7（新增）：分享奖励做成后台配置

**作者意见：** 细则未想死；奖励可含 AI 次数、发信次数；可同时开或单独开。

**评估：正确。** 用配置驱动，避免改代码调数值。

**拍板：通过。** 配置项建议：\share_reward_enabled\、\
eward_ai_quota\、\
eward_send_quota\、\daily_share_reward_cap\、\cooldown_seconds\ 等。

**「如何保证真的分享了？」——诚实结论：移动端无法 100% 证明。** 可执行折中见 §5.4。

### 5.3 「未拍板词」解释（答作者：这些是什么意思？）

| 词 | 含义 | 建议默认（供你拍） |
|----|------|-------------------|
| **模板 5 题** | 写信前的结构化倾诉模板，降低空白页恐惧。例如：焦虑时写给自己 / 想放下的事 / 想鼓励自己 / 想记住的瞬间 / 对未来的小期待。后台可改文案。 | 先定这 5 题方向，文案可开工时再润色 |
| **删代码还是开关** | 笔友 Tab、商店等：从仓库删实现，还是留代码用开关隐藏？删=干净但阶段 2 要重做；开关=阶段 2 快，仓里仍肥。 | **阶段 1：UI 入口隐藏 + 路由不可达**；商店用户面可删。不必物理删光后端匹配表 |
| **英文名** | 系统/商店英文名。现为 \Senior Post\。中文既定「时光邮局」后，英文是否改 \Time Post\ 等。 | 可后定；不挡中文上线 |
| **寄出锁定例外** | 「寄出后不可读正文」的边界：封缄前能否预览？草稿？误寄能否短窗口撤回？信封页显示什么？ | 封缄前可预览；封缄后不可读全文；首版不做撤回 |

### 5.4 分享「真伪」如何处理（可执行折中）

移动端系统分享页打开后，用户可以取消；App **收不到**「已发到朋友圈」回执。

| 方案 | 可信度 | 成本 | 建议 |
|------|--------|------|------|
| 调用系统分享面板成功返回就发奖 | 低（可取消） | 低 | **可作主方案**，必须配日上限 |
| 用户勾选「我已分享」再领奖 | 低 | 低 | 可叠加 |
| 要求先「保存图片」再分享 | 中低 | 低 | 可作步骤，仍可刷 |
| 服务端检测外链打开/商店归因 | 中 | 高 | 独立开发不做 |
| 人工审核 | 高 | 高 | 不做 |

**拍板建议：** 不追求「保证真分享」，追求「奖励成本可承受」：分享面板调起并返回 → 计 1 次；**每日奖励次数上限**（可配）；同信重复分享不重复奖；可关奖励总开关。
