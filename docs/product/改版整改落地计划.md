# 时光邮局 5.0 整改落地计划（以用户间通信为本体）

> 版本：2026-08-17 · 分支：`feature_5.0` · 状态：冷启动口径已按作者 08-17 确认修订，待下令开工
> 关联：[`改版方向讨论稿.md`](./改版方向讨论稿.md)（产品决策记录）、[`产品价值与用户吸引逻辑.md`](./产品价值与用户吸引逻辑.md)（价值讨论）
> 本文作用：把“用户间通信为本体、时光信为冷启动补位”的讨论结论，落成**需求规则 + 工程计划 + UI 评估与调整建议**。以 §9.2（2026-08-17）为准；与旧段冲突时，以 §9.2 覆盖。

---

## 0. 战略前提（先纠偏，再落地）

1. **产品本体是用户与用户之间写信**：陌生有缘人（邮局池）+ 指定笔友（DIRECT）。慢信、封缄、在途、拆封是体验，不是工具。
2. **时光信不是主产品**：它只承担两个角色——
   - 冷启动池子空时，给用户一个“确定性期待”，避免寄给陌生人后死寂；
   - 满足本来就只想写给自己的偏好用户。
3. **冷启动默认主推时光信，池子有密度后由作者在管理后台手动切到「寄给有缘人」**：后台展示池子状态；首页 CTA **不**按算法自动切换。
4. 小而精，冷启动只打“愿意写 / 愿意等 / 愿意回访”；愿意回信等作者在后台切到有缘人后再验。
5. 独立开发、低获客投入、先留存后付费、只赚小钱。

## 2. 改版需求规则（落地后的产品宪法）

### 2.1 主路径与闭环

```text
静默进入 → 动态首页 → 写信给真实的人（有缘人 / 指定笔友）
  → 封缄 → 在途（不可读正文）→ 到期/匹配送达 → 拆封 → 回信 → 成为笔友
```

- 首日反馈：寄出“给有缘人”后，立刻收到一封**明确标注“邮局欢迎信”**的系统信，完成第一次“寄出 → 在途 → 拆封”。
- 支线：时光信（写给未来自己）作为等待补位与偏好分支；寄往邮局支线保留但降预期。

### 2.2 鉴权

- 首次打开：用设备身份静默创建访客账号，直接进入主路径。
- 注册/绑定后置：在 AI、付费、换机/清数据、用户自愿，以及**写信产生信资产后（寄出第一封信时）**引导绑定，避免换机/清数据丢信。
- 登录保留：“我的”始终提供登录入口，已绑定账号可登回。
- 注册流程瘦身：不再强制 8 步、不强制 ≥3 兴趣标签、不强制性别/出生年。

### 2.3 首页主推（管理后台手动切换）

首页主 CTA **不**按池子算法自动切。由作者在管理后台看池子状态后，手动选择主路径：

| 后台开关 | App 主按钮 | 次级入口 |
|----------|------------|----------|
| `TIME_LETTER`（上线默认） | **写给未来的自己** | 寄给有缘人（文案降预期） |
| `POST_OFFICE` | **寄给有缘人** | 写给未来的自己 |

护栏：
- 前端只渲染后台下发的 `recommendedAction`，不在客户端判断池子；
- 邮局文案降预期：“寻找有缘人，可能需要几天”；
- **不做「邀请朋友当笔友」入口**：App 尚未建立信任，冷启动用户基本不会选；已有笔友关系仍可从信箱「我的笔友」写信（DIRECT 能力保留、入口不主推）。

### 2.4 写信分流与话题 chips

写信入口二选一（顺序跟后台主推走）：

1. 寄给有缘人（邮局池，无收件人）；
2. 寄给未来的自己（时光信）。

指定笔友（DIRECT）不进首页分流；仅信箱内「我的笔友」对已有关系可见。

写信话题 chips（信维度，单选、可跳过，5 个）：

| chip | 匹配作用 |
|------|----------|
| 心事倾诉 | 优先给愿意倾听、回信温和的人 |
| 生活分享 | 按语言/国家/活跃度投，话题兼容性要求低 |
| 兴趣交流 | 可结合兴趣标签或内容做软排序 |
| 人生困惑 | 优先给回信质量高、有耐心的人 |
| 随便聊聊 | 兜底，几乎不挑人 |

“兴趣交流”可选二级领域：文娱 / 运动 / 科技 / 生活 / 学习 / 其他；单选、可跳过。

### 2.5 系统欢迎信

- 用户寄出第一封“给有缘人”后，立即收到系统欢迎信；
- 明确标注“邮局欢迎信”，不伪装真人；
- 内容告知：信已进入邮局、正在寻找有缘人、可能需要几天；
- 让“寄出成功”成为首日成功事件，真人回信成为 D7 惊喜。

### 2.6 轻量匹配规则（扩展现有 v2，静默冷启动可用）

按顺序执行：

1. **硬过滤**：语言一致（设备 locale）；未被拉黑/举报；有可回信空位。
2. **候选排序**：愿意接待新信 > 历史回信率 > 国家/地区距离 > 话题 chips 匹配。
3. **新用户优先**：新用户来信优先匹配给“可接待新信”的种子/老用户。
4. **兜底**：无人可接待则进入等待队列，首页诚实显示“仍在寻找有缘人”，并引导时光信/邀请朋友。

匹配权重、可接待开关、额度上限、新用户优先窗口期全部做成后台配置。

### 2.7 兴趣标签与话题 chips 的关系

- **兴趣标签（人维度）**：长期、多选，存 `bu_user_tag`，用于阶段 2 找笔友/推荐。
- **写信话题 chips（信维度）**：一次性、单选，存 `bu_letter.topic_tag_id`，用于本封信即时路由。
- 底层复用一套标签库：`sys_tag` 加 `tag_type`（`INTEREST` / `LETTER_TOPIC`）。
- 阶段 1 兴趣标签基本不参与匹配，只顺手采集；阶段 2 再作为长期匹配主力。

### 2.8 时光信角色

- **冷启动主路径**：池子空时，首页主推“写给未来的自己”，保证用户有确定性的等待与回访；
- 池子有密度后，降为偏好分支，用户间通信回到主位；
- 首封只暴露“下周”档位，下月/90 天在首封拆封后解锁，先把闭环跑短；
- 首封可接受“一句话也算一封信”，降低写作门槛。

### 2.9 分享与奖励

- 首版只做长图分享，不做 H5；
- 优先做“刚寄出时的信封卡”（信封/邮戳/倒计时，不露正文），隐私顾虑小、传播强；正文卡二期；
- 奖励配置化：`share_reward_enabled` / `reward_ai_quota` / `reward_send_quota` / `daily_share_reward_cap` / `cooldown_seconds`；
- 不追求“证明真分享”，调起分享面板返回即计一次，配合每日上限 + 总开关；
- 奖励尽量用“解锁限定信纸”替代直接送次数，减少通胀与刷量动机。

### 2.10 AI 与付费

- AI 只留“润色 + 灵感”两键，去掉五模式；
- 今日寄语 AI 日更，按天缓存复用 + 用户维近 N 天去重 + 兜底池；
- 首封赠送少量 AI 次数，拆封后再送，控制 token 成本；
- 第一付费点 = AI 高级次数（寄过一封后露出），替换旧商店。

### 2.11 安全底线（保留）

- 敏感词前置、审核/举报/拉黑、额度限制、异常登录风控；
- UI 少暴露审核/风控术语。

## 4. 当前 UI 评估

设计语言整体值得保留：Postal 复古邮局视觉、信封/邮戳/纸感、适老化字号与触控尺寸都是资产。问题主要出在**信息架构、首屏路径、注册墙和入口权重**。

### 4.1 欢迎 / 注册 / 登录

- **问题**：强制注册登录墙 + 8 步注册 + 强制 ≥3 兴趣标签，是当前最大的激活摩擦；与“静默可用”冲突。
- **评估**：这是 4.0 最需要推翻的页面。

### 4.2 邮局首页

- **问题**：有“写信”主 CTA，但被“领取额度”强制弹窗打断；写信分流只有两个入口，且缺少“邀请朋友”；没有动态主推，也没有“信已进入邮局、正在寻找有缘人”的状态感。
- **评估**：结构对，但首屏优先级和冷启动状态反馈不足。

### 4.3 写信桌

- **问题**：单页写信桌体验不错，但收件人 sheet 只有两个选项，没有话题 chips；AI 五模式选择过载；首封没有“一句话即可”的降门槛引导。
- **评估**：核心交互底子好，需要收敛入口和 AI。

### 4.4 信箱

- **问题**：三 Tab（收到/发出/时光信）逻辑清晰，已有在途横幅；但“等待匹配”状态不够诚实，用户看不到“我的信还在找人”与“已找到人、在路上”的区别。
- **评估**：保留，补状态区分。

### 4.5 笔友页

- **问题**：推荐/找笔友/我的笔友三 Tab 像社交平台，冷启动时大量空态，与“小而精、用户间写信”冲突。
- **评估**：阶段 1 应撤出主导航，笔友关系沉到信箱。

### 4.6 我的

- **问题**：商店/VIP/导出/收藏入口过重，且“注销请求”英文字符串硬编码；与“只赚小钱、先留存”不符。
- **评估**：做减法，保留绑定登录、资料、兴趣标签、设置。

### 4.7 时光信列表 / 拆封

- **问题**：功能已有，但与主路径权重需要重新摆正；首封档位选择应更短。
- **评估**：保留体验，调整入口权重与档位顺序。

## 5. UI 调整建议（落地）

### 5.1 底部导航：四 Tab → 三 Tab

- 保留：邮局（写信/首页）、信箱（收发/时光信/笔友往来）、我的（绑定/资料/设置）。
- 移除“笔友”Tab；“我的笔友”作为信箱内的一个列表/分组。

### 5.2 首页：后台主推 + 减法

- 顶部问候 + 今日寄语保留；
- 主 CTA 只跟 `recommendedAction`：
  - `TIME_LETTER`：主按钮“写给未来的自己”，次按钮“寄给有缘人（可能需要几天）”；
  - `POST_OFFICE`：主按钮“写一封信给有缘人”，次按钮“写给未来的自己”；
- 无「邀请朋友」按钮；
- 去掉“每日领取额度”强制弹窗，改为轻提示或静默发放。

### 5.3 写信桌：入口与 AI 收敛

- 收件人 sheet 二项，顺序跟 `recommendedAction`：主推项在前；无邀请朋友；
- 正文上方加“这封信想聊什么”5 个 chips，单选、可跳过；
- “兴趣交流”选中后可选露出二级领域；
- AI 助手只保留“润色”和“灵感”两个入口，去掉五模式选择页；
- 首封写“给有缘人”或“给未来自己”时，提示“一句话也可以”，降低空白页恐惧；
- 时光信首封只显示“下周”，更长档位拆封后再解锁。

### 5.4 信箱：区分“等待匹配”与“在途”

- 列表状态三态清晰：
  - 等待匹配：“仍在寻找有缘人”；
  - 在途：“已找到有缘人，预计 N 天送达”；
  - 已送达：“可以拆封”；
- “我的笔友”作为信箱内分组/入口，展示笔友往来列表；
- 系统欢迎信单独置顶或醒目标注“邮局来信”。

### 5.5 我的：减法

- 移除商店/VIP 主入口；导出/收藏后置或深藏；
- 保留：绑定邮箱/手机、登录、资料编辑、兴趣标签、隐私、设置；
- 修复硬编码英文字符串，统一走 l10n。

### 5.6 欢迎/注册：静默化

- 移除强制欢迎页/注册墙；首次打开直接静默创建设备账号并进入首页；
- 注册流程改为“绑定”流程，极简：邮箱（可选）+ 密码，资料后置；
- 首日通过后台主推的写信入口引导，而非资料问卷。
- 寄出第一封信后，弹一个可跳过的轻绑定提示（“信已在路上，建议绑定账号，避免换机丢信”）。

## 6. 数据与后端改动要点

| 层 | 改动 |
|----|------|
| 标签 | `sys_tag` 加 `tag_type`（`INTEREST` / `LETTER_TOPIC`） |

| 鉴权 | 设备 `device_uuid` 静默创建访客用户；绑定/登录保留 |
| 首页 | 新增动态主推所需状态接口：池子等待时长/可接待人数/在途数 |
| 推送 | 到达推送文案池；拆封前不露正文 |

## 7. 工程里程碑与任务拆解

### P0 — 最小闭环（验证用户愿意留下来，为 App 积累用户）

目标：跑通“静默进入 → 按后台主推写信（默认时光信）→ 封缄 / 在途 / 拆封 → 回访”；不把真人回信当上线验收。

- 前端：三 Tab；藏找笔友 / 商店 / VIP；首页按 `recommendedAction` 渲染主 CTA；AI 两键；首封「一句话也可以」；时光信首封只下周；
- 后端：静默注册（guest user）；绑定/登录保留；额度静默；`recommendedAction` **读后台配置**（非算法）；
- 管理后台：展示池子状态（等待匹配数 / 可接待人数等）+ 手动切换主路径 `TIME_LETTER` / `POST_OFFICE`；
- 验收：新用户无需注册即可寄出第一封；作者能在后台看到池子并切换首页主推；商店/VIP/找笔友对用户不可见。

### P1 — 留存加深与有缘人加重

## 10. 需求细则（开发落地口径）

> 目的：把“一次开发不返工”所需的细节写清楚。以下以“新增开发”为前提，明确要做到什么程度，而不是纠结现状缺什么。

### 10.1 静默注册与账号生命周期

- 首次打开 App：客户端读取现有 `DeviceInstallId` 得到 `device_uuid`，调用新增 `POST /api/auth/guest`。
- 请求字段：`deviceUuid`、`deviceType`、可选 `language`、`countryCode`、`latitude/longitude`。
- 服务端：按 `device_uuid` 查找已有 user；无则创建真实 user（`status=1`），并写 `bu_user_device`。不创建邮箱 identity。
- guest 是“静默注册的真实用户”，不是游客态：拥有完整 user 行，具备发信/收信/拆封能力，走正常 `/api/**` 鉴权。
- 默认值：nickname 可为空或“匿名寄信人”；country 取 locale/GeoIP；language 取设备 locale；不校验年龄/性别/兴趣标签。
- 返回 `AppAuthResultVO`，与正常登录一致（含 token、user、`firstLetterDone=false`）。

### 10.2 绑定升级与登录保留

- 绑定触发点：寄出第一封信后（轻提示可跳过）、使用 AI 前、付费前、“我的”主动绑定/登录。
- 绑定流程：邮箱 + 密码（或 Google）；把 `bu_user_identity` 挂到当前 user，**不新建 user**。
- 登录：凭已有 identity 登回同一 user；换机/清数据后资产保留。
- 绑定页只收邮箱 + 密码；性别/出生年/兴趣标签全部后置到“我的-编辑资料”，可选。
- 寄出第一封信后的绑定提示文案：“信已在路上，建议绑定账号，避免换机丢信”；可跳过，不阻断主路径。

### 10.3 系统欢迎信

- 触发：用户寄出第一封“给有缘人”成功后，立即生成并投递一封系统欢迎信。
- 发件人模型：`LetterDomain` 增加 `source_type`（`USER` / `SYSTEM`）；系统信 `from_user_id=0`（或系统账号常量）。
- 投递：同步送达，不走匹配池，`status=DELIVERED`。
- 内容：告知“信已进入邮局、正在寻找有缘人、可能需要几天”。
- 展示：信箱“收到”列表置顶，醒目标注“邮局来信”；不显示真人头像/昵称。
- 边界：只对“给有缘人”首封触发一次；时光信首封不触发。

### 10.4 首页主推（配置下发 + 后台手动切）

- `GET /api/post-office/home` 增加字段：
  - `recommendedAction`：`TIME_LETTER` / `POST_OFFICE`（**读 `sys_config`，不由算法计算**）；
  - `poolWaitCount` / `canMatchNow`：可给 App 状态卡用，但 **不驱动** 主 CTA。
- 管理端新增（或挂到现有配置页）：
  - 只读池子状态：等待匹配数、可接待人数、在途数；
  - 主路径开关：`home.recommended_action` = `TIME_LETTER` | `POST_OFFICE`，上线默认 `TIME_LETTER`。
- 前端只按 `recommendedAction` 渲染主 CTA；次级入口为另一条写信路径。无「邀请朋友」。
- 不设自动切换阈值。

### 10.5 写信分流与话题 chips

- 写信入口二选一（顺序跟 `recommendedAction`）：寄给有缘人 / 写给未来的自己。指定笔友不进此 sheet。
- 话题 chips：单选、可跳过，5 个：心事倾诉 / 生活分享 / 兴趣交流 / 人生困惑 / 随便聊聊。
- “兴趣交流”选中后显示二级：文娱 / 运动 / 科技 / 生活 / 学习 / 其他；单选、可跳过。
- 数据：`bu_letter.topic_tag_id` 存所选 chip 的 tag id；二级领域首版存内容 meta 或扩展 tag。
- 匹配：topic 只做软排序，不阻塞匹配。

### 10.6 轻量匹配（扩展现有 v2）

- 保留 `PostOfficeMatchService` 现有：语言兼容、回信率 boost、入站上限、黑名单、新用户优先。
- 新增：`willing_to_receive_new`（硬过滤）、`topic_tag_id`（软排序）、`active_penpal_capacity`（可回信空位）。
- 候选排序：愿意接待新信 > 回信率 > 国家距离 > 话题匹配。
- 兜底：无人可接待 → 进入等待队列，首页显示“仍在寻找有缘人”。

### 10.7 每日额度静默化
